# 前言　写给要负责的人

## 这本书为什么存在

我做后端这些年，见过的最贵的故障，没有一个是"服务挂了"。

挂掉的故障有告警、有值班、有预案，处理得再糟也就半小时。真正贵的，是那些**不报错**的：

- 库存多扣了 347 件，订单表干净，日志没有一条 ERROR
- 用户改了昵称，三小时后才生效，因为缓存里是旧值
- 消息 `send success`，但对端从来没收到
- 监控上错误率 0.00%，客诉 40 单

它们的共同形状是：**代码看起来完全正确，框架按文档工作，SQL 也执行了，错的只有数据。**

而数据错了，要等到对账、客诉、第二天早上，才会有人知道。

市面上讲原理的书很多，讲"为什么你的原理没生效"的书很少。这本书想补这个空。

## 给谁看

工作 3–5 年、已经在线上扛过责任的 Java 后端。

如果下面这些话你说过其中一句，这本书就是写给你的：

- "本地跑得好好的啊。"
- "这个注解我加了呀。"
- "下游说他们没问题，我们也说我们没问题。"
- "重启一下试试？"
- "这个接口以前没这么慢。"

如果你还在准备面试、需要的是知识覆盖面，这本书不合适——它故意不追求完整。

## 怎么读

**不要从头读。** 按你正在经历的事跳：

| 你在经历什么 | 读哪几章 |
|---|---|
| 接口慢，但下游监控正常 | 第一章、第四章 |
| 加了注解不生效 | 第六章（事务）、第八章（循环依赖） |
| 数据错了，不知道谁改的 | 第十五章（缓存一致性）、第十九章（重复消费） |
| 消息丢了 / 重复了 / 堆了 | 第十八、十九、二十章 |
| 线上炸了，要先取证 | 第二十三、二十四章 |
| P99 有周期性毛刺 | 第二十五章 |
| 要过一遍复盘 | 第二十七章 |

全书五卷，是一条读者的真实经历线：**请求进来 → 业务跑起来 → 数据落地 → 异步与峰值 → 上线之后出事。** 顺着读也没问题。

## 每一章的形状

统一六段，你可以直接当检查表用：

1. **现场** —— 什么时间、什么现象、影响多少
2. **误判** —— 当时怎么想的、为什么错（这一段教科书里没有）
3. **根因** —— 原理层解释，一到两层，不发散
4. **修复** —— ❌ 错误写法 → ✅ 修复写法
5. **自检清单** —— 可以直接贴进 CR 模板
6. **延伸** —— 主线之外、但值得知道的支线深挖，以及指向知识库对应原理篇的指针

## 难度分层：怎么看【必读】【进阶】【选读】

这本书想同时服务两类读者：**工作 3–5 年、正在第一次撞上这类坑的人**，和**已经踩过、想看清机制为什么这么设计的人**。所以每一章按难度分了三层：

- **【必读】** —— 主线。一个故障从现场到修复的完整链路，跳过任何一段都讲不清楚。3–5 年读者吃透这一层就够了。
- **【进阶】** —— 深挖。框架为什么这么设计、源码里哪一行走到了这里、公式怎么推出来。想从「会用」到「懂为什么」再看，跳过不影响主线。
- **【选读】** —— 延伸。同一类问题的其它变种、冷门边界、可以直接抄的清单。备查，不要求通读。

每章开头有一行「难度构成」告诉你这章有几处进阶、几处选读；小节标题前的标签让你随时知道自己在哪一层。看到【选读】可以放心跳，看到【进阶】可以放心放一放。

## 交叉引用索引

书里反复出现几条「跨章才能讲清」的主线。为了避免每章都重讲一遍，约定：**主场章节把原理讲透，其它章节只引用、不重述**。这张表是它们的地图：

| 跨章主线 | 主场（讲透） | 其它现场（只引用） |
|---|---|---|
| Little's law：`L = λ × W`（排队论容量） | 第四章（连接池容量公式） | 第一、二、七、九、十三、十四、十七、二十一、二十五章 |
| 事务里做远程调用 / 行锁持有时间 | 第七章（整章） | 第四、六、十四、二十二章 |
| 加线程的负收益（排队型故障加线程只拉长队伍） | 第七章 | 第十三章（加机器同结论）、第二十章（积压场景加线程仍有效，互补） |
| 超时链路：`HTTP < 事务timeout < 锁等待 < 调用方` | 第七章、第十四章 | 第四、二十二章 |
| 幂等与去重 | 第十九章 | 第四（本地消息表）、第二十二章（防超卖） |
| 缓存一致性 | 第十五章 | 第三（序列化）、第十六章（缓存问题） |
| 连接池被事务占满 | 第四章 | 第六、七章 |
| 对账兜底（丢失/重复的最后防线） | 第十八、十九章 | 第二十二章 |
| 全链路减法定位（两处指标相减找差值） | 第一章、第四章 | 第七章 |

正文里凡出现「见第 X 章」都按这张表走——主场讲了原理，这里只代入本系统的参数。

## 关于案例

**书里的现场由多个真实故障脱敏合成，代码、数字、时间线经过改写。** 结论对应真实的排查路径，不是虚构的。

这样做有两个原因：一是保护当事人和相关业务；二是单个真实故障的信息量往往不够支撑一章——把三四个同类故障拼在一起，才能把"这一类问题"讲清楚。

## 这本书不写什么

明确说出来，省得你找：

- **Java 语法**：网上有更好的，最多在需要时提一句
- **面试题**：那是检索型内容，不该线性读
- **框架怎么用**：官方文档比我写得准
- **架构方法论**：DDD、中台这些，不是这本书的主题

它只讲一件事：**当系统不报错、但结果是错的时候，怎么找到原因。**

代码与配置基于：

```
JDK 17 / 21
Spring Boot 3.x（部分章节标注 2.7 的差异）
MySQL 8.0
Redis 7.x
RocketMQ 5.x / Kafka 3.x
```

框架默认值会变，但**"默认值是给 demo 用的"这条判断不会变**。看到具体数值时，请以你手上的版本文档为准；看到判断逻辑时，可以直接用。
